🚀 Modernisation Update

HLStatsX, Rebuilt: leaving legacy PHP and Perl behind for modern .NET

The original HLStatsX stack served the community for years, but both the PHP site and the Perl backend now feel every bit like legacy systems: ageing, unloved, and effectively unmaintained. HLStatsX.NET is the answer — a modern C# rewrite focused on performance, security, maintainability, and privacy without losing the soul of the platform, with the backend daemon already partially ported as part of that journey.

⚡ Performance-first 🛡️ Security-aware 🔧 Maintainable architecture 🔒 Privacy-minded
Legacy vs rewrite

How HLStatsX.NET compares to the old PHP and Perl stack

Area Legacy PHP + Perl stack HLStatsX.NET rewrite
Architecture Split across older PHP and Perl components, with increasing complexity and growing difficulty evolving safely. Layered C# solution with clearer boundaries across Core, Infrastructure, and Web, plus a backend daemon that has already been partially ported.

Performance Functional, but built around older patterns and legacy processing paths with less predictable optimisation options. Async-first services and repositories, modern runtime performance, and a cleaner basis for profiling and tuning. ⚡
Security Legacy surface area, ageing dependencies, and older backend scripts that increase operational risk over time. Modern ASP.NET Core defaults, stronger dependency management, and a better foundation for secure development. 🛡️
Maintainability Every change becomes harder as multiple legacy codepaths drift further from active maintenance. Typed models, dependency injection, testability, and safer future refactoring. 🔧
Privacy Older codebases rarely make privacy considerations easy to evolve or audit. Modern configuration and data handling practices make privacy improvements much more realistic. 🔒
Momentum Historically important, but effectively stuck in time. Actively moving forward, feature-by-feature, with room for polish and expansion. 🚀

Why this rewrite matters

The PHP frontend and Perl backend proved the idea. The C# rewrite will secure the future.

HLStatsX has always been more than a stats page. It is part scoreboard, part social layer, part historical archive for Half-Life server communities. But the legacy PHP website and Perl backend come from another era. They are harder to evolve, harder to secure, and harder to trust for long-term growth. When a codebase stops being actively loved, even simple improvements become expensive and risky.

That is why this project is not just a port. It is a deliberate rebuild on modern .NET, with a cleaner architecture and a sharper engineering focus. The aim is to retire both the ageing PHP presentation layer and the legacy Perl processing path, then replace them with a unified platform that is faster, safer, and easier to extend. Importantly, this is already underway: the backend daemon has been partially ported to C#, proving the modernisation effort reaches beyond the web UI. 🙂

⚙️ Modern stack ASP.NET Core on .NET 10, with C# and a layered architecture designed for long-term development across both web and backend responsibilities.
🗄️ Flexible database future The new data layer is being shaped to support MySQL, PostgreSQL, and SQL Server, reducing lock-in and broadening deployment options.
🧠 Clear separation of concerns Core, Infrastructure, and Web are cleanly separated, making refactoring and testing far safer.
❤️ Work in progress with momentum This is already useful today, and the path forward is stronger than the legacy branch ever was, with the backend daemon partially ported to C# already.
📊 Feature parity in motion The current front-end effort is already substantial: public stats pages are roughly 55% complete, with overall weighted parity around 45% and many of the most important read-only pages already live.
At a glance
  • 🏚️ Legacy problem The original PHP site and Perl backend are valuable historically, but old, unloved, and increasingly difficult to maintain safely.
  • 💡 Rewrite answer HLStatsX.NET replaces legacy implementation debt with a modern C# and ASP.NET Core foundation, with the backend modernisation story included.
  • 📈 Current state Major user-facing pages already exist in the current web project, and a separate C# ingest daemon effort already includes parsers, handlers, replay tooling, and event-processing infrastructure.
  • 🌍 Long-term promise Better performance, better security, better maintainability, broader database choice, and a more privacy-conscious platform for the community.

Engineering priorities

Performance, security, maintainability, and privacy are not buzzwords here

  • ⚡ Performance Modern .NET gives the rewrite a stronger execution model, while async data access, cleaner query paths, bounded-channel ingest, and batched event processing create far better conditions for real optimisation work.
  • 🛡️ Security Rebuilding on ASP.NET Core means modern framework support, clearer dependency management, and a platform that can keep pace with security expectations instead of trailing behind them.
  • 🔧 Maintainability Strong typing, testability, dependency injection, and separation between layers make this codebase one that can replace scattered PHP and Perl logic with something that can be extended confidently rather than feared.
  • 🗄️ Database portability The new platform is being built with support for MySQL, PostgreSQL, and SQL Server in mind, giving operators more freedom in how they host, scale, and integrate HLStatsX.NET.
  • 🔒 Privacy A stats platform handles player activity and server data. The rewrite provides a cleaner foundation for privacy-aware features, clearer configuration, and better operational discipline.

Great things will follow

HLStatsX.NET is still a work in progress, and that is exactly what makes it exciting. The foundation is already modern. The direction is already clear. The feature set is already growing. This rewrite is not about nostalgia — it is about ensuring HLStatsX has a future worth building on, from the website right through to the backend processing stack. 😎
